# 개발 명세 v0.1
Vue3 + TypeScript, FastAPI, Python 엔진, MySQL, LangGraph, Ollama/Qwen. 엔진이 권위 상태를 소유하고 AI는 구조화된 행동 제안만 생성한다.
## 명령 계약
POST /runs/{id}/orders: expected_version, idempotency_key, duration_minutes, interrupt_policy(all|critical|none), delegate_emergency_response, retain_active_orders, orders[]. 검증 실패 시 상태 불변. GET /runs/{id}/state, /events, /intel. 시간은 정수 분. 동시 명령은 충돌 검사. 저장과 이벤트는 단일 트랜잭션.
## 전투 및 이동
부대별 병과·병력·사기·피로·탄약·위치·목표·지휘관. 지역 그래프의 이동 시간과 수용력, 정찰 신뢰도, 전령 이동을 별도로 처리. 전투 결과는 시드 기반 난수와 엔진 규칙으로 산출. 초기 공식은 미확정이며 기존 대화의 임시 공식을 확정 규칙으로 사용하지 않는다. 사상자와 회복은 별도 이벤트. 독립군은 요청 수신 후 AI가 수락/거절/수정.
## 시간 진행
none은 요청 종료까지 진행, critical은 성 함락·지휘관 사망 등 명시적 필터, all은 주요 사건. 중단 후 잔여 시간 자동 재개 금지. 전후 10~365일 정책 턴과 일별 생산·소비 집계. 치명적 사건은 로그에 기록.
## 내정·외교·정치
포로 의료 적격→승인→실제 인계 순서. 귀환민과 직속 병력 분리. 외교 합의는 발효 시점과 기한 종류 명시. 지방 성주 독립 시 병력 소유권 자동 이동 금지. 관등·직책·친밀도·신뢰·경계 별도 필드. 자원 지수와 실제 물량을 혼용하지 않는다.
## AI / 정보
역할별 목표·성격·기억·허용 도구. AI 호출은 접촉·명령 수신·정책 기한 등 이벤트 기반. timeout 또는 형식 실패 시 안전한 방어/대기. 적군 사실 상태와 플레이어에게 전달된 첩보를 분리. 보고에는 observed_at, received_at, confidence 포함.
## 구현 순서
1. 상태 스키마와 회계 테스트. 2. 시간·전령·이동. 3. 전투와 지역 지도. 4. AI 제안 검증. 5. 전후 정책·외교. 6. UI 및 재현 테스트. 분기 B는 기준 기록이지 강제 결말이 아니다.
