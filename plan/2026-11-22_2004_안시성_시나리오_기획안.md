# 해동연의 첫 시나리오 · 안시성의 불멸

작성: 2026-11-22 20:04 (KST)

상태: 구현 전 계획

## 산출물

PC와 모바일 브라우저에서 열 수 있는 정적 HTML 기획안. 시나리오 선택 화면에 〈안시성의 불멸〉 한 편을 제시하고, 진입하면 5국 세력지도, 거점 상태, 인물 능력치와 열전을 살펴볼 수 있다. 고구려·백제·신라·왜·당별로 인물 100명씩, 총 500명의 편성표를 제공한다. 기획안의 시연 범위는 첫 내정 명령을 내리기 직전까지다.

## 화면과 시나리오

1. **시나리오 선택** — 645년을 역사적 배경으로 표시한다. 안시성 수비와 구원군의 연결을 플레이 목표로 제시한다. 시작 카드에는 전황과 초기 목표, 진입 버튼을 둔다.
2. **세력지도** — 시나리오 시작 시점의 5국 세력권과 주요 연결로를 개념도로 표현한다. 세력과 거점은 터치로 조회할 수 있게 한다. 개념도에 표시되는 세력권·도로·해로의 위치는 게임용 도식임을 명시한다. 모바일에서 지도와 같은 정보에 접근할 수 있도록 거점 목록을 둔다.
3. **거점 상세** — 소속, 기능, 담당 인물, 주둔군, 방어 상태, 군량, 연결 거점을 표시한다. 담당 인물과 연결 거점을 누르면 각각의 상세 화면으로 이동한다.
4. **인물 목록과 열전** — 국가, 역할, 사료 상태, 시나리오 배치 여부로 조회하고 이름·이명으로 검색한다. 인물 상세에는 통솔·무력·지력·정치·외교, 시나리오 배치, 사료 근거, 요약 열전을 표시한다. 수치를 제시할 때는 게임 설계값으로 표시한다.
5. **내정 직전 브리핑** — 첫 명령 전에 거점별 과제와 가용 인물을 확인한다. 기획 흐름은 준비 3턴과 턴당 명령 2개를 잠정안으로 둔다. 성벽 보수·군량 수송·병력 재배치·정찰·구원 요청이 각각 방어 상태·비축·초기 배치·첩보·예상 도착 시점에 어떻게 이어지는지 보여준다.

기존 시나리오북의 상대 17일 10시 START는 전투 기준 상태로 연결한다. 토산 53%와 구원군 출진은 기존 START 자료로 보존하고, 준비 시작 시각은 신규 설계값으로 별도 정의한다. 준비 이후에는 군령과 상황에 따라 구원군 합류, 토산 공방, 휴전 또는 함락으로 분기한다.

## 초기 지도 편성

| 세력 | 거점 후보 | 시나리오 기능 |
|---|---|---|
| 고구려 | 안시성, 오골성, 평양, 건안성 | 방어, 군량 수송, 조정·구원 요청, 요동 방어 |
| 백제 | 사비, 신라 접경 전선 | 조정과 외교, 접경 전황 |
| 신라 | 서라벌, 매리포성 | 조정과 외교, 접경 방어 |
| 왜 | 야마토 조정, 해상 교섭 거점 | 조정 변화, 대외 사절 |
| 당 | 장안, 요동성, 백암성, 안시성 외곽 진지 | 원정 지휘, 전방 보급, 공성 |

초기 후보는 14개다. 점령 상태는 시나리오 시작 기준으로 결정한다. 접경 전선과 해상 교섭 거점은 도식용 노드로 분류한다. 오골성에서 안시성으로 이어지는 보급과, 당의 요동성에서 외곽 진지로 이어지는 보급을 우선 표시한다.

## 국가별 100인 편성

- 국가마다 100명의 고유 인물을 최종 편성한다. 착수 시 국가별로 출처 후보 목록을 만들고, 실명 확인 인원·전승 인원·창작 인원·부족 인원을 각각 집계한다. 공란과 중복은 완성 인원으로 집계하지 않는다.
- 645년 무렵 활동 근거가 있는 인물을 우선 배치한다. 앞뒤 세대까지 조사하되 활동 시기가 다른 인물은 해당 시기의 열전 항목에 배치하고, 645년 시작 병력과 지휘 명단에는 포함하지 않는다. 군주·관료·사절은 해당 역할로 표시한다.
- 창작 장수는 전체 500명 중 최대 5명을 초안 기준으로 둔다. 기존 설정집의 전술상 핵심 배역부터 남긴다. 조사 후 국가별 100명 목표 달성에 필요한 시대 범위나 역할 범위의 변경은 근거와 부족 인원을 제시해 판단한다.
- 양만춘은 전승 이름과 안시성주 배역을 기록한다. 고연수는 실존과 작품 내 성내 지휘 배역을 별개로 기록한다. 고연수·고혜진, 당 태종·이세적, 의자왕·김유신, 왜 조정의 고토쿠·나카노오에를 출처 대조의 첫 묶음으로 삼는다.

## 개발 지침

- 구현에 앞서 [기존 개발 지침](../docs/HAEDONG_v1.0/06_Codex/AGENTS.md)의 선행 문서를 읽는다. [시나리오북](../docs/HAEDONG_v1.0/02_Scenario/SCENARIO_BOOK.md)과 [인물 설정집](../docs/HAEDONG_v1.0/03_Characters/CHARACTER_BIBLE.md)을 시작점으로 사용한다.
- 역사 H, 기존 게임 G, 신규 설계 N, 미확인 U를 필드별로 관리한다. 역사 인물 여부와 게임 배역의 근거를 분리하고, 사료의 기사·권차·URL을 기록한다. 미확인 값은 데이터에서 `null`, 화면에서 `미확인`으로 표시한다. v0.1 원본과 기준 저장점은 읽기 전용으로 취급한다.
- HTML·CSS·JavaScript로 정적 구현하고, 시나리오·인물·거점 자료는 화면 코드와 분리한다. 고정 ID로 연결하며, 이명은 같은 인물에 묶는다. 모바일에서 지도 터치, 목록과 상세 이동, 키보드 포커스, 뒤로 가기를 검증한다.
- 거점 주둔군, 독립 구원군, 부상병, 포로, 군량, 수레는 각각 별도 필드로 관리한다. 장차 엔진 기능을 붙이는 단계에서는 기존 Python 엔진의 권한, 회계, 재현성 지침을 적용한다.
- 이후 계획 문서는 저장소의 단일 `plan/` 폴더에 한국시간 기준 `YYYY-MM-DD_HHmm_이름.md`로 저장한다. 새 계획은 파일을 추가하고 변경점과 이전 계획 링크를 남긴다.

## 구현과 검증 순서

1. 5국 사료 조사와 기존 데이터 대조를 시작하고, 국가별 목표와 등록 현황을 집계한다. 화면 시연에 필요한 대표 인물과 거점부터 등록한다.
2. 시나리오 선택, 지도, 거점, 인물 열전, 내정 직전 브리핑의 탐색 흐름을 구현한다. 데스크톱과 모바일에서 메뉴와 링크를 확인한다.
3. 500인 편성표를 완성하고 국가별 고유 인물 100명, 사료 상태 표기, 창작 장수 수, 시대·거점·인물 참조 무결성을 검증한다. 열전마다 사료 또는 작품 설정 근거에 접근할 수 있는지 확인한다.
4. GitHub Pages 배포 산출물은 기획안 전용 폴더로 준비한다. 저장소 `channyworks/haedong`에서 배포할 때는 GitHub Actions로 해당 폴더만 올리는 방식을 예정한다. 게시 범위와 공개 여부가 결정된 뒤 배포하고, 실제 URL을 모바일 화면 크기에서 확인한다. 이후 승인된 변경이 배포 브랜치에 반영될 때 사이트가 갱신된다.
